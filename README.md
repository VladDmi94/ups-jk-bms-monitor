# ups-jk-bms-monitor (Go)

Легковесный сервис на Go для превращения аккумулятора с **JK BMS (BD4A8S4P)** в полноценный ИБП (UPS) для Windows.

Скрипт подключается к BMS по Bluetooth Low Energy (BLE), считывает телеметрию в режиме пассивного стриминга, рассчитывает оставшееся время работы, отправляет уведомления в Telegram при отключении/возобновлении питания и автоматически завершает работу Windows при критическом разряде.

---

## ⚡ Особенности

- **Пассивный BLE-стриминг (`JK02_32S`)**: Инициализация выполняется командами `0x97` и `0x96`, после чего плата вещает данные автономно.
- **Детекция питания с гистерезисом**: Порог тока разряда установлен в `-0.1 A`, чтобы исключить ложные срабатывания от микротоков балансировки или шумов ups.
- **Расчёт автономного времени**: Время работы высчитывается динамически на основе **сглаженного** тока разряда (EMA, alpha=0.1) и реального SOC (%):
  
  $$\text{Remaining Ah} = \text{Capacity} \times \frac{\text{SOC}}{100}$$
  $$\text{Run Time (hours)} = \frac{\text{Remaining Ah}}{\vert{}\text{Smoothed Current}\vert{}}$$
  
  Сглаживание (экспоненциальное скользящее среднее) убирает «прыжки» из-за микротоков балансировки и шума, но за ~10 с подстраивается под реальное изменение нагрузки.

- **Telegram Уведомления**: Гибкая настройка задержки отправки (`DELAY_NOTIFY`), чтобы не спамить в чат при кратковременных скачках напряжения.
- **Предупреждение о низком заряде**: Разовый алерт в Telegram при SOC ≤ `LOW_BATTERY_THRESHOLD` (по умолчанию `20%`), чтобы успеть сохранить работу до аварийного выключения.
- **Автоматическое выключение ПК**: При достижении порога `SHUTDOWN_THRESHOLD` (например, $\le 10\%$) инициирует корректное завершение работы Windows (`shutdown /s /t 30`).
- **Предупреждение о высокой температуре**: Разовый алерт в Telegram при превышении `TEMP_THRESHOLD` (по умолчанию `69 °C`) по любому из датчиков MOS / T1 / T2. Повторно срабатывает только после отката всех датчиков ниже порога на `TEMP_HYSTERESIS` (по умолчанию `5 °C`).
- **Логирование**: Параллельный вывод событий в консоль и локальный файл `ups_log.txt`.

## 🛠 Требования

1. **ОС**: Windows 10 / 11 (с поддержкой Bluetooth LE).
2. **Аппаратная часть**: JK BMS (проверено на `BD4A8S4P`, HW `15H`, SW `15.41`).
3. **Go**: Версия `1.20+` (используется библиотека [`tinygo.org/x/bluetooth`](https://github.com/tinygo-org/bluetooth)).

## ⚙️ Настройка конфигурации (`.env`)

Создайте файл `.env` в корневой директории проекта рядом с `main.go` или бинарным файлом:

```env
TARGET_BMS_NAME=YOUR_BMS_NAME_HERE
BATTERY_CAPACITY_AH=YOUR_BATTERY_CAPACITY_HERE_IN_AMPERE_HOURS
TELEGRAM_TOKEN=YOUR_BOT_TOKEN_HERE
TELEGRAM_CHAT_ID=YOUR_CHAT_ID_HERE
DELAY_NOTIFY=5            # Задержка перед отправкой алерта в Telegram (в секундах)
SHUTDOWN_THRESHOLD=5      # Порог SOC (%) для аварийного выключения Windows
LOW_BATTERY_THRESHOLD=20  # Порог SOC (%) для предупреждения о низком заряде в Telegram
SHUTDOWN_TIMEOUT=30       # Тайм-аут перед выключением Windows (в секундах)
STALE_SHUTDOWN=0          # Тайм-аут потери связи с BMS (с) для завершения работы (0 - не отключать ПК)
TEMP_THRESHOLD=69         # Порог температуры (°C) для предупреждения в Telegram
TEMP_HYSTERESIS=5         # Откат (°C) ниже порога, после которого алерт может повториться
LOG_FILE=ups_log.txt

```

## 🔌 Подключение к BLE-стриму (принцип работы)

> **Важно при любых правках кода подключения.** Ниже описан рабочий протокол, подтверждённый
> тестами на `BD4A8S4P` (HW `15H`, SW `15.41`) и сверен с референсной реализацией
> [esphome-jk-bms](https://github.com/syssi/esphome-jk-bms).

### Последовательность команд

BMS **не начинает стримить** сразу после подключения. Требуется:

1. **`0x97` (Device Info)** — отправить **один раз** после установки подписки на уведомления.
   BMS отвечает кадром `0x03` (метаданные устройства).
2. **`0x96` (Cell Info / Real-time Data)** — отправить **повторно** с интервалом ~2 с,
   **пока** не придёт кадр `0x02` (телеметрия). BMS отвечает на каждый `0x96` кадром `0x01`
   (ACK), но **начинает стримить** только на N-ом повторе (N зависит от состояния BMS,
   обычно 1–5).

### Типы кадров

| Тип | Назначение | Когда приходит |
| :--- | :--- | :--- |
| `0x01` | ACK / confirmation | В ответ на каждую команду `0x96` |
| `0x02` | Real-time data (телеметрия) | После «пробуждения» стрима, затем постоянно |
| `0x03` | Device Info (метаданные) | В ответ на `0x97` |

### Почему `0x96` нужно повторять

BMS после переподключения (или после простоя) **не всегда начинает стримить** с первого `0x96`.
Референсная реализация (ESPHome) шлёт `0x96` **каждый `update_interval`** (по умолчанию 15 с),
**пока** не получит кадр `0x02`. Наш код делает то же самое: `kick()` повторяет `0x96`
каждые 2 с в течение 30 с.

### Ключевые константы в `main.go`

| Константа | Значение | Назначение |
| :--- | :--- | :--- |
| `kickTimeout` | `5 s` | Максимум на одну команду (защита от зависшего `awaitAsyncOperation`) |
| Интервал повтора `0x96` | `2 s` | Как в ESPHome `update_interval` |
| Максимум ожидания стрима | `30 s` | Если за 30 с нет `0x02` — сессия считается мёртвой, `bmsLoop` переподключает |

### Референсы

- **ESPHome**: [`jk_bms_ble.cpp`](https://github.com/syssi/esphome-jk-bms/blob/main/components/jk_bms_ble/jk_bms_ble.cpp)
  — `update()` шлёт `COMMAND_CELL_INFO` (0x96) пока `status_notification_received_ == false`.
- **Формат команды**: `AA 55 90 EB <cmd> <len> <value[4]> <CRC>` (20 байт, CRC = Sum8 первых 19).
- **UUID сервиса**: `0000ffe0`, **характеристики**: `0000ffe1`.

### Частые ошибки при правках

- **Убрать повтор `0x96`** → BMS не «проснётся», стрим не запустится.
- **Отправить `0x97` после `0x96`** → BMS отвечает `0x03`, но **не начинает стримить**.
- **Ждать `0x02` после первого `0x96`** → таймаут, потому что BMS ещё не «проснулся».
- **Забыть `0x97`** → BMS может не перейти в режим стрима (зависит от прошивки).

## 📌 Архитектура кадра данных (`JK02_32S`)

Кадр телеметрии `0x02` имеет фиксированный размер **300 байт**. Проверка целостности выполняется по младшему байту суммы первых 299 байт (`Sum8 CRC == frame[299]`).

### Кадр метаданных (Frame `0x03` — Device Info)

| Параметр | Смещение (Байты) | Тип данных | Описание |
| :--- | :--- | :--- | :--- |
| **Модель устройства** | `6 : 21` | `string` (ASCII, null-trimmed) | Название модели (напр., `JK_BD4A8S4P`) |
| **Ревизия железа (HW)** | `22 : 29` | `string` (ASCII, null-trimmed) | Версия планера/HW (напр., `15H`) |
| **Версия прошивки (SW)** | `30 : 37` | `string` (ASCII, null-trimmed) | Версия ПО (напр., `15.41`) |

### Кадр телеметрии (Frame `0x02` — Status Telemetry)

| Параметр | Смещение (Байты) | Тип данных | Множитель | Ед. изм. |
| :--- | :--- | :--- | :--- | :--- |
| **Напряжение ячеек 1..8** | `6 + (i * 2) : 7 + (i * 2)` | `uint16` (LE) | `0.001` | V |
| **Напряжение сборки (Total V)**| `150 : 153` (`118+32`) | `uint32` (LE) | `0.001` | V |
| **Ток (Current)** | `158 : 161` (`126+32`) | `int32` (LE) | `0.001` | A |
| **Температура MOS** | `144 : 145` | `int16` (LE) | `0.1` | °C |
| **Температура T1** | `162 : 163` | `int16` (LE) | `0.1` | °C |
| **Температура T2** | `164 : 165` | `int16` (LE) | `0.1` | °C |
| **Уровень заряда (SOC)** | `173` | `uint8` | `1.0` | % |
| **Чексумма (CRC)** | `299` | `uint8` | `Sum8(frame[0..298])` | — |
